Standard Promotion Workflow

Phase 1: Pre-Flight Checks

  1. Navigate to Checks page
  2. Verify all critical checks pass (green)
  3. Address any failures before proceeding
  4. Warnings (amber) are informational — note them but you can proceed

Phase 2: Dev → Stage

  1. Navigate to Promote page
  2. Review the file diff to confirm expected changes
  3. Click Promote to Stage
  4. The system will:
    • Auto-commit any uncommitted dev changes to git
    • Create a stage DB backup
    • Create a stage code snapshot
    • Run promote.sh to copy changed files
    • Clear .pyc caches
    • Restart odoo-stage service
    • Run smoke tests (HTTP, XML-RPC, /shop)
    • Create a git tag (stage-YYYYMMDD-HHMMSS)
  5. Verify the smoke test results show green

Phase 3: Stage Validation

  1. Visit https://stage.priorityblinds.com.au
  2. Browse /shop — verify products render
  3. Check images display correctly (CSP fix verified)
  4. Test any new features or fixes
  5. If issues found: rollback via the Rollback page

Phase 4: Stage → Production

  1. Ensure stage validation is complete
  2. Navigate to Promote page
  3. Type PROD in the confirmation field
  4. Click Promote to Production
  5. The system will:
    • Create a prod DB backup (CRITICAL)
    • Copy tracked files from stage to prod
    • Clear .pyc caches
    • Restart odoo service
    • Run prod smoke tests
    • Create a git tag (prod-YYYYMMDD-HHMMSS)
  6. Monitor production for at least 5 minutes
Rollback Procedures

Stage Rollback

  1. Navigate to Rollback page
  2. Find the promotion to roll back, or use "Rollback Stage (Latest Backup)"
  3. Click Rollback Stage
  4. System stops stage, restores DB + code from backup, restarts

Production Rollback

  1. Navigate to Rollback page
  2. Type PROD in the confirmation field
  3. Click Rollback Production
  4. System stops prod, restores DB from pre-promotion backup, restarts
  5. Monitor production for 5 minutes after rollback
